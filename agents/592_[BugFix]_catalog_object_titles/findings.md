# Findings
Current recovery ignores generated object filenames as sources but only replaces title values containing charset corruption. A stored obj hash can therefore survive even when a readable logical filename exists. Use logical filenames as evidence and preserve known embedded titles, release identity and source bytes.
Music source access remains restricted to Z; repository audit records and cloud catalog metadata remain available. No local music scan is needed for the initial database inventory.

User clarified search3 returns the objects. Read-only authenticated production search3 with an existing valid SSO session showed 0 object-like titles and 499 physical objects/obj_* paths in the first 500 songs. Source inventory found 5767 object-backed available originals, all with exactly one logical storage entry. Child.path exposed the physical storage key instead of the original logical filename. The correction is an API projection/filename-recovery fix, not a catalog rename operation.

Independent review found empty capability submissions and no-tag scans becoming accepted without readable filename evidence in the first draft. The follow-up retained rejection for no-tag/no-readable-path uploads and scanned=2 for unrecoverable no-tag scans. Reviewed final source has no blocking issue. Added a deterministic instance-id tie-break to the paired album URI/logical-path selection so metadata hints refer to the same instance under equal quality.

Current live deployment includes KtvRoom and MediaContainer bindings absent from the old Windows private config. Prepare an ignored isolated config from live settings and container resource/image snapshots, preserving all four DO bindings, both existing container images/resources, current plaintext settings, all existing secrets through keep-vars, and both cron schedules. Use containers-rollout none; do not rebuild or mutate container apps. Dependency synchronization was necessary for the upstream @cloudflare/containers package. A private config generator initially had a bracket syntax error; fixed before any deployment.
