# KTV rooms and video media

## Requirements
- Bind a temporary room to the current site and playback instance. The request page and its APIs are unavailable outside an active room.
- Guests choose a display name; a stable room participant identity survives refresh and renaming.
- Support per-person round-robin and first-requested-first-played scheduling.
- Support independent library audio, Bilibili/YouTube video, and library audio bound to a specified video. Bound video is muted and follows the audio clock with a saved offset.
- Load video and timestamped danmaku through maintained media tooling.
- Implement Subsonic video browsing, details, media delivery and captions according to the upstream protocol.
- External requests remain temporary; only an explicit host save adds a video to the catalog.
- Audio and video are distinct catalog objects. Links are many-to-many; each audio/video pair carries its own offset. Removing a link never removes either medium.
- A video can be played as video or listened to as audio-only without creating or reclassifying an audio object. Mode switches retain the playback position.

## Scope and decisions
- Work from the latest fetched origin/main in an isolated worktree. Preserve unrelated primary-checkout changes separately.
- The old KTV plan is historical evidence only; neither origin/main nor the retained feature branch contains the modules it lists.
- Reuse the existing Vue, Hono, storage and external-transcoder architecture. Establish shared media contracts before delegating independent implementation work.
- Follow the user's instruction not to add new test cases. Run existing relevant tests, type checking and real local request/playback checks.
- Production deployment remains a separate gate from source integration and push.
- Browser playback owns its disposable media session; Subsonic caches a separate user/video/revision session so closing a web player cannot terminate another client.
- Prefer HLS.js where Media Source Extensions are available. The local browser's native HLS path failed on an otherwise retrievable stream; HLS.js completed video and audio-only playback.
- Rewrite complete HLS manifests and omit upstream byte-range and entity headers because rewritten resource URLs change the byte representation.
- Save external metadata without retaining a playback session, avoiding exhaustion of the media service's bounded session pool during catalog imports.
- Use SQLite Durable Objects for room authority and leases, while keeping permanent catalog objects and many-to-many links in D1.
- CLI setup is documented for the new binding and database tables. The existing installer and in-app updater do not provision this new Durable Object automatically; release packaging must account for this before distribution.

## Shared implementation contracts
- `videos` is a standalone catalog, separate from `song_masters`; `video_audio_links` has a composite unique audio/video key and a per-pair offset.
- Persistent links do not select a global preferred video. The room queue snapshots the concrete audio/video selection for each request.
- The external media service extends `docker/external-transcoder` and reuses its configured URL and secret. Worker media calls use `worker/src/media/loader.ts`.
- Service sessions return `{ id, title, duration, width, height, expiresAt, audioTracks, captions }`. Secrets and expiring upstream URLs remain within the service.
- Native inputs are uploaded as streamed bytes to `/media/files`; external platform inputs use `/media/resolve`. Authenticated session artifacts provide video streams, HLS, captions and danmaku.
- Independent service work is delegated in its own worktree. The primary agent retains room architecture, audit records, review and final integration.
