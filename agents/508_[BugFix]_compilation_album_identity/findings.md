# Initial findings

- Production primary read shows `SSParty!!` split into 14 one-track FLAC albums, all with year 2020 and tracks 1–14 under the same `SSParty!!（无词/` storage folder. Each track has a different `album_artist`; the album name is identical. This is one compilation, not 14 editions.
- The metadata apply path in `worker/src/utils/metadataApply.ts` derives album IDs from `albumArtist || artist` plus album name. The legacy `worker/src/endpoints/tag/read.ts` follows the same pattern. When per-track album artists differ, each track receives a different album ID despite sharing one source folder.
- A broad read-only primary query found many more same-name, single-track fragments. The candidate list requires album path, edition, track-order, and reference checks before data consolidation. A simple name-only merge would be unsafe.
- Existing `retainCompilationAlbum` only helps when the current album already has `compilation=1`; new uploaded tracks begin in the placeholder album, so it cannot prevent this fragmentation.
- `SSParty!!`'s 14 R2 instances have the same `source_id` and exact `storage_entries.parent_id`, complementary track numbers 1–14, one FLAC codec, and one 2020 album title. This is a strong source-folder identity. Its old numeric master IDs and `si-mirror-*` instance IDs show that historical mirror/tag ingestion is affected, not only the current manual upload path.
- Current direct manual uploads create masters in `pending-uploads` and already have a `storage_entries` row with `instance_id`, `source_id`, `parent_id`, and path before metadata apply. `applyMetadataResult` has the exact instance ID; `tag/read` also reads it. A source-folder anchor can prevent new compilation fragments while allowing codec subfolders to remain separate versions.
- `test/internal/album_artist_roundtrip.test.ts` currently verifies that explicit artist edits on an established non-compilation album can change album identity. The import fix should preserve this behavior and target initial ingestion or source-folder reparse; explicit edit semantics should remain deliberate.
- No name-only production merge is safe. A separate data audit should group by source folder, album title, codec, release context, complementary track numbers, and user references before guarded updates.
- A second primary D1 aggregate grouped by normalized album name, exact source folder ID, source ID, and codec. Examples with fully complementary non-null tracks include `异色合鸣Chromatic Harmony` (18 album rows, 24 distinct tracks), `SSParty!!` (14 rows, 14 tracks), `Emotional Things（Deluxe）` (12 rows, 30 tracks), `初音ミク マジカルミライ 2020 Official Album` (10 rows, ten WAV files but missing track tags), and many others. Some titles have two separate full source folders or missing track tags; these require separate release/version review. This confirms a library-wide ingestion identity defect, not an isolated alias.
- [Navidrome's persistent-ID documentation](https://navidrome.org/docs/usage/configuration/persistent-ids/) supports folder-based album identity as an explicit grouping choice, while its default uses release IDs and album artist/title/version/date. [Its FAQ](https://www.navidrome.org/docs/faq/) explains that varying artist tags split a compilation unless the compilation tag or a suitable identity is supplied. This supports a source-folder anchor for this import workflow, with track artist credits kept separate and codec editions distinct.

## Decision

- Initial metadata ingestion from `pending-uploads` uses a deterministic ID from source ID, exact parent folder ID, codec suffix, and normalized album name. The entry must be unique for the instance. This joins a release whose tracks carry different artist credits while keeping separate folders and formats as separate editions. Existing album tag edits keep their established identity behavior.
- When such an imported album contains different track artists or album artists, set `albums.compilation=1`. Track-level artist and album artist IDs are preserved. This prevents later artist-only edits from splitting the compilation under the existing tag-edit rules.
- The code fix prevents new fragments; it deliberately does not mutate historical album rows. Historical consolidation is tracked in the separate folder-fragment audit.
