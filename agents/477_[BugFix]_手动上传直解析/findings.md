# Findings

- Baseline main: `2a5f1e2b90137e6cfa5987fddb737f197d138fbb`.
- Existing browser path parses and submits metadata directly, while the upload endpoint unconditionally dispatches an `origin=upload` priority-3 task. The browser extractor skips covers, so the task currently supplies embedded art.
- General `/tag/submit` requires `edit_tags`; upload requires `upload`. The new browser path needs a narrowly scoped capability tied to the authenticated uploader and instance, not a relaxation of general tag permissions.
- Work queue remains the fallback for non-browser/API uploads and for direct parse/submit failures. Lyrics already flow through `applyMetadataResult`; the direct request must keep this field and include the embedded cover.
- The new upload capability binds the username, instance ID, and current `storage_uri`; overwriting the same instance rotates the URI and invalidates stale capabilities. It expires after 30 minutes and fails closed when `WORK_UPLOAD_HMAC_KEY` is unavailable.
- Existing audio overwrite is rejected before writing bytes unless the caller has `edit_tags`. New audio instances may receive initial metadata through the capability; general `/tag/submit` remains permission-gated.
- Browser direct submit marks the instance scanned and prevents sequential capability replay. A failed embedded-cover write can queue a deduplicated retry only while the target album has no cover pointer; queued worker processing reuses the same no-overwrite cover helper.
- Scheduled R2 scans call `asyncScanR2Source` without `dispatchToWorkerPool`, so they do not recover uploads when the browser closes before metadata submission. A separate hourly cron recovery now queues at most 50 aged `si-upload-*` original instances with `tag_scanned=0`, `missing=0`, and no metadata work-queue row in any state; the 10-minute minimum age avoids racing the normal browser parse. This recovery is independent of `scan_interval_hours` and does not repeatedly retry terminal task histories.
- Explicit API/direct-failure/cover-retry enqueue checks the deterministic task row first. Queued and claimed tasks are left untouched; completed/failed/canceled tasks can be requeued using an atomic terminal-status WHERE guard. General force-rescan `upsert` semantics are unchanged.
- The first target test run exposed an incomplete test fixture (`source_type`) and an outdated mock matcher/priority bind index; both were corrected. No production D1/R2 or deployment commands were run.
- Follow-up review found that same-URI overwrites need a random upload generation in both the pending marker and capability subject; metadata queue payloads also carry that generation. Old claims with mismatched URI/generation stay unresolved, and stale queued work is refreshed before the marker is consumed.
- A recovery marker is consumed only after a queued/claimed task payload matches the current upload. The direct metadata endpoint retains the marker after an embedded-cover write failure so scheduled recovery can retry it.
- Embedded-cover CAS now writes unique object keys, checks the committed pointer after ambiguous D1 results, cleans a loser only after confirming it is unreferenced, and reports saved/preserved/invalid accurately.
- The work-queue submit endpoint now checks the task instance id, source URI, and upload nonce against the current instance and durable generation marker before applying tags. Successful generations remain as completed marker rows so later claimed stale results are still distinguishable; deployments without a newer marker retain legacy task behavior.
- Existing-instance audio overwrite writes the new generation marker and resets tag_scanned before any R2/WebDAV PUT. Failed or ambiguous transfers keep the marker and unscanned state so scheduled recovery reparses the current persisted URI; recovery repairs a future URI marker to the instance URI when the database update never completed.
- WebDAV target existence is authoritative for the upload-only overwrite guard; an absent D1 instance no longer permits replacing a physical audio file.
- Global agents project/task index files were removed from this branch as they belong to the root checkout's untracked state.
