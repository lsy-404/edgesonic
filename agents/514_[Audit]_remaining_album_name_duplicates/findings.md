## Alternate-instance playback feasibility

- Frontend playback addresses a song master ID and offers a global quality selector with `auto`, `flac`, and `wav`. The stream endpoint resolves all non-missing instances for that master and, for an explicit codec request, selects a stored instance with the requested suffix when available. Therefore a WAV instance attached to the existing FLAC track 14 master would be playable through the existing WAV quality choice; there is no per-track source/instance chooser.
- `song_masters` owns the displayed title and track metadata; `song_instances` has storage/codec properties but no per-instance title field. The pending WAV track 14 is titled `14 ONE SEIF` on its separate master, while album track track 14 is `ONE SELF`. Reassigning the WAV instance to the FLAC master would make playback work, but the library/player would display the master title `ONE SELF` for either file. The original WAV filename remains represented by its source-tree path, but the UI does not surface it as an alternate title. Keep the separate pending master until a deliberate title/variant representation is chosen.
- This schema/UI behavior makes a display-group edition the safer preservation model when each encoding has distinct track identity or album metadata. For 2024 创作, pending WAV tracks 1–13 plus its existing WAV track 14 can form a WAV edition while the current keeper's FLAC tracks 1–13 form the FLAC edition; keep all masters, objects, lyrics, credits, and tree entries, and link the two album rows in one display group. This is a design proposal only; no candidate or production change was made here.
